# Integração BET — ambiente de teste restrito
Não publicar a main nem abrir vendas ainda. O checkout público existente continua intacto.
Este protótipo cria assinatura pendente independente por UID, pois a API exige token de cartão para assinatura vinculada a plano existente. Confirma os sete dias, BRL 19,90 e recorrência antes de devolver o checkout. Se o Mercado Pago não aceitar free_trial nesse fluxo, bloqueia e exige revisão; não oferece cobrança imediata. O token TEST- e um UID de teste novo são obrigatórios. Não usar conta da proprietária.
No Cloud Shell do projeto autorizado, clonar este branch, entrar em functions, executar npm install e npm test. Na raiz, executar firebase functions:secrets:set BET_MP_TEST_TOKEN --project bet-hebraico (colar somente no terminal), e configurar BET_TEST_UID com UID de uma conta nova de teste ao solicitar o parâmetro. Antes de deploy, revisar custos e IAM. Com Firebase CLI autenticada: firebase deploy --only functions:betStartTest,functions:betSyncTest,functions:betCancelTest --project bet-hebraico. Nenhum deploy foi realizado pelo GitHub.
O branch inclui somente backend de teste. Chamar as funções callable pelo SDK Firebase autenticado. Testar checkout, retorno, sincronização, expiração, cancelamento e estornos em ambiente de teste. A liberação só é gravada após consulta autenticada ao provedor. A sincronização ainda é sob demanda; webhook assinado e reconciliação periódica precisam ser implementados antes de produção. Validar comportamento real do período grátis e datas de fatura, inclusive atrasos e cancelamentos. Não reutilizar tentativa com estado creating/review sem checar se houve criação no provedor.
